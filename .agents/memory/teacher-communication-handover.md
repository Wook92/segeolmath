# 교사소통(teacher_student_messages) 인수인계 정책

대화는 `(teacherId, studentId)` 조합으로 그룹화된다. 수업 담당 교사가 바뀌면 학생 입장에서 기존 대화가 "고아"가 되어 화면에서 사라지는 문제가 있었다. 이를 다음 규칙으로 처리한다.

## 결정 규칙
- **승계 = teacherId만 재작성**: 메시지의 `teacherId`만 새 교사로 바꾸고 `senderId`/`receiverId`는 보존한다.
  - **Why:** 과거 발신/수신 이력을 그대로 보존하기 위함. 단, unread 집계는 `receiverId===teacherId` 기준이라 과거 미읽음은 새 교사에게 승계되지 않는다(의도된 트레이드오프 — 신규 교사에게 과거 미읽음 폭탄을 주지 않음).
- **자동 승계는 보수적으로만**: 담당 변경(PATCH class) 시, 이전 교사가 해당 학생과 다른 연결(담임 또는 다른 수강 수업)이 전혀 없을 때만 이관한다. 연결이 남아 있으면 대화 도난을 막기 위해 이관하지 않는다.
- **고아 복구(reconcile)도 보수적으로**: 학생이 수강 수업 1개 + 고아 대화 1개인 명확한 경우에만 자동 이관. 다중일 때는 손대지 않는다.
- **읽기 노출 vs 이관 분리**: 학생/학부모 화면 선생님 목록은 "담임 + 수강담당 + 대화이력" 교사를 모두 반환해 숨김을 방지한다(이관이 안 돼도 이력 교사 카드로 노출됨).
- **부작용 있는 reconcile는 GET 금지**: 고아 복구를 수행하는 communication-teachers 엔드포인트는 POST로 노출한다(읽기 경로에서 mutation 금지 원칙).

## 권한 검증(필수)
- 학생 본인 / 연결된 학부모(`linkedStudentIds` 포함 또는 학생의 `parentId` 일치) / 같은 센터 소속 교직원(`getUserCenters`로 centerId 소속 확인)만 학생 대화·선생님 목록 접근 가능.
- **Why:** role만 보고 통과시키면 임의 studentId 조회로 권한 누수가 발생함(코드리뷰 블로커였음).

## 이전/현재 선생님 메시지 구분(UI)
- 인수인계 시 `teacherId`만 새 교사로 바뀌고 `senderId`는 원발신자로 남는다. 따라서 **교사 메시지 중 `senderId !== teacherId`이면 "이전 담당" 선생님 메시지**로 판정해 시각적으로 구분한다.
  - **Why:** 메시지에 sender role/name이 별도로 없어 클라이언트가 두 ID 비교로 추론한다.
  - **How to apply:** "이전 담당" 판정 전에 반드시 발신자가 교사인지 가드해야 한다(관리자/원장 발신이 이전담당으로 오분류 방지). 학생 화면엔 발신자 이름 맵이 없으니 센터 교사 목록 + 이력 교사 목록으로 이름을 해석한다. 교사 이름 해석용 쿼리는 학생/학부모/원장뿐 아니라 **일반 교사 로그인에서도 활성화**해야 교사 뷰에서 구분이 깨지지 않는다.

## handover 실패 정책
- 담당 변경 시 handover 실패는 catch로 삼키고 클래스 수정은 계속 진행(비차단). 메시징 실패로 핵심 수업 변경을 막지 않기 위함. 실패는 로그로만 남는다 — 운영자 재처리 수단은 추후 보강 대상.

## 읽음 처리 정책 / 미읽음 "1" 표시 (KakaoTalk식)
- **미읽음 소거 기준 = 실제 수신자(`receiverId`) 본인이 읽었을 때만**. 원장/관리자가 대화를 열람해도 "다른 선생님이 수신자"인 메시지의 미읽음은 줄지 않는다(목록 배지 unread = `receiverId===teacherId`).
  - **Why:** 원장 열람만으로 담당 교사의 미읽음이 사라지면 담당 교사가 메시지를 놓친다.
  - **How to apply:** 원장이 본인이 수신자(`receiverId===원장`)인 메시지는 읽음 처리해야 목록 빨간 "1"이 사라진다. 단, "전체(all)" 보기 GET 경로는 teacherId가 없으므로 teacherId 무관하게 `receiverId===readerId`만 읽음 처리하는 별도 경로가 필요(특정 교사 보기 GET은 기존 markMessagesAsRead로 이미 처리됨). 원장 read는 클라 PATCH가 아니라 서버 GET 단계에서 일어난다(클라 useEffect는 원장 분기에서 캐시 무효화만).
- **채팅방 내 메시지 옆 "1" (안읽음 표시)는 직원(선생/원장/관리자) 화면 전용**. 본인 발신(`isMine`) && `!isRead`일 때만 노출. 학생/학부모(`isStudent`=STUDENT+PARENT)는 별도 렌더 블록을 써서 "1"이 노출되지 않음.
